# 🔄 工作流程 —— 学 / 完善 / 推广三套日常流程

> 你只需要记住三句话：**每天学一课，想加就提需求，每周推一次。**

## 一、学习流程（每天 20-40 分钟）

1. 打开 `docs/LEARN.md`，从当前课开始（第 1 课 → 第 7 课）
2. 读完一课 → 动手做该课的"动手"环节（跑任务 / 看状态 / 排查）
3. 用自己的话在 `docs/NOTES.md`（新建）写 3 行笔记：这课讲了什么 + 我哪里还不懂
4. 不弄懂的挂到"待问"清单，攒着一次性问

> 判定标准：7 课学完 = 能对着项目讲 15 分钟。

## 二、完善流程（想加功能时）

```
提需求 → 我评估 → 实现 → 你验证 → 提交发布
```

1. **提需求**：直接说"我想加 XXX"（参考 `docs/ROADMAP.md` 里的候选，或自由发挥）
2. **我评估**：按"价值/难度"排期，告诉你预计效果
3. **实现**：我写代码 + 自动测试 + 更新 README
4. **你验证**：刷新页面试功能，说"OK"或"哪里不对"
5. **提交**：验证通过后 git commit（我准备好 commit 信息）
6. 每实现一个，回 `docs/ROADMAP.md` 把 `[ ]` 划成 `[x]` 并写验证方式

## 三、推广流程（发布与内容）

| 频率 | 动作 | 产出 |
|---|---|---|
| 一次性 | `docs/PROMOTE.md` 第 1-2 步 | GitHub 仓库 + 3 分钟演示视频 |
| 第 1 个月 | 第 3 步 | 第一篇博客（我帮你改稿） |
| 每周 | 第 4 步 | 1 条社区内容（博客/视频/回答） |
| 每月 | 第 5 步 | 1 篇复盘 |

## 四、项目治理（版本与发布）

- **版本号**：README 顶部写 v0.x（现在 v0.5）
- **提交规范**：一次改动一个提交，信息里写"做了什么 + 为什么"
- **发布检查**：提交前跑三件事——
  1. `python3 -c "import ast; ast.parse(open('server.py').read())"`（后端语法）
  2. 浏览器刷新页面（前端正常）
  3. `curl http://127.0.0.1:8787/api/state`（服务健康）

## 五、遇到卡住（30 秒自救）

1. 服务没反应 → 看 `server.log` 最后 10 行
2. 任务不动 → `/api/state` 看 pendingApprovals / run 状态
3. 都正常但页面怪 → 浏览器 Ctrl+Shift+R 硬刷新
4. 还不行 → 把现象 + server.log 发我
